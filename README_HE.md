# מנתח Rule #1

מזינים סימול של מניה אמריקאית ומקבלים ניתוח לפי כללי הספר של פיל טאון (Rule #1 ו-Payback Time).

## הפעלה

```
cd C:\Users\matan\rule-one-analyzer
python server.py
```

ואז לפתוח בדפדפן: http://127.0.0.1:8765

לפני ההפעלה הראשונה צריך קובץ `config.local.json`, שלא עולה ל-git:

```json
{ "sec_contact_email": "your@email" }
```

ה-SEC מחייב לצרף מייל-קשר לכל בקשה.

## מבנה

| קובץ | תפקיד |

| `server.py` | שרת מקומי. מגיש את `public/` ומשמש תחנת ביניים דקה ל-SEC ול-Yahoo, עם מטמון בדיסק (`.cache/`) |
| `public/rule1.js` | מנוע החישוב, טהור ובלי רשת. כל כללי הספר נמצאים כאן |

| `tests/rule1.test.mjs` | בדיקות אוטומטיות: `npm test` |

## מקורות נתונים

- **דוחות:** ממשק ה-XBRL של ה-SEC (`companyfacts`). נלקחים רק דוחות שנתיים מסוג 10-K. כשיש כמה ערכים לאותה תקופה, הערך מההגשה האחרונה גובר (כולל תיקונים בדיעבד).
- **מחירים:** Yahoo chart: 15 שנים חודשי (למכפיל ההיסטורי ולספליטים) ושנה יומית (לכלים הטכניים).
- **ספליטים:** כל ערך של רווח למניה או של מספר מניות מתוקן לפי הספליטים שקרו אחרי תאריך ההגשה שלו.

## כללים כפי שמומשו

- **חמשת המספרים:** ROIC (ממוצע), ומכירות, EPS, BVPS ו-FCF (קצב צמיחה שנתי ממוצע) לאורך 10, 5, 3 ושנה אחת. הרף הוא 10%.
  "עסק נהדר" = לפחות 4 מדדים עוברים, ואף מדד לא נכשל לגמרי.
- **ROIC** = רווח תפעולי אחרי מס, חלקי (הון עצמי + חוב לטווח ארוך).
- **צמיחה לפי הספר:** הנמוכה מבין צמיחת ההון העצמי ההיסטורית (החלון הארוך ביותר שיש לו נתונים) לבין הערכת אנליסטים, אם הוזנה.
- **מכפיל עתידי:** הנמוך מבין פי 2 משיעור הצמיחה לבין המכפיל ההיסטורי. המכפיל ההיסטורי מחושב כחציון ולא כממוצע, החלטה שלנו, כדי ששנה חריגה לא תעוות.
- **מחיר הסטיקר:** EPS × (1+g)^10 × מכפיל, חלקי 1.15^10. מחיר הקנייה הוא 50% ממנו.
- **Payback Time:** כמה שנים של FCF למניה, שגדל בקצב g, צריך כדי להחזיר את המחיר. הרף הוא 8 שנים.
- **שלושת הכלים:** MACD (8,17,9), סטוכסטיק (14,5), ממוצע נע 10 ימים. כניסה כשכל השלושה ירוקים.

## גרסת האינטרנט (GitHub Pages)

בכל ערב של יום מסחר (22:30 UTC) רץ `.github/workflows/pages.yml`. הוא:
1. מריץ את הבדיקות.
2. מושך את רשימות S&P 500 ו-Nasdaq-100 מוויקיפדיה. אם המשיכה נכשלת, הוא משתמש ב-`scripts/tickers_fallback.json`.
3. בונה `data/<TICKER>.json` לכל מניה (`scripts/build_data.py`). מניה שנכשלה מקבלת את הקובץ מאתמול.
4. מפרסם את האתר יחד עם הנתונים. הנתונים לא נשמרים ב-git, כדי שההיסטוריה לא תתנפח.

המייל ל-SEC שמור כסוד במאגר (`SEC_CONTACT_EMAIL`) ולא בקוד. ריצה ידנית: לשונית Actions, ואז Run workflow.
